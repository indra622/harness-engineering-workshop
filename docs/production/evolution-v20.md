# v20 변경 메모: OMH 사례 이어서, OMP로 옮긴 경험

v20은 v19(45장)의 14쪽 OMH 사례 바로 뒤에 한 장을 넣어 46장이 됐다. 새 15쪽은 사례 2를 이어 가는 화면이다. 여섯 번째 사례나 네 번째 참고 화면이 아니다. 용어 25, 사례 5, 참고 3은 그대로다.

## 사용자 요청

- OMH 설명 뒤에 한 장을 넣는다.
- OMP로 옮겨 보니, 직접 덧붙였던 것은 omh-rigorous 스킬을 빼면 이미 바탕 하네스에 들어 있었다.
- 며칠 들여 v05까지 만든 것이 허무했고, v06은 v05보다 얇게 정리할 수 있었다. 이 경험이 맺음말의 '공부할수록, 오히려 확신이 줄었어요'의 바탕이다.
- 14쪽과 맺음말 문구는 바꾸지 않는다.

## 15쪽 화면, '며칠을 만들었는데, 옮겨 보니 이미 있었다'

- **세 단계 도식:**
  - OMH v05: OpenCode + OMO 위에 키 큰 '직접 덧붙인 부분'(역할 조율, 실행과 도구 연결, 업무 도구, omh-rigorous 절차).
  - OMP로 옮김: 점선 상자 '직접 덧붙일 필요가 없어짐'이 'OMP 기본 기능'(파일 읽기, 쓰기, 편집 / 명령 실행 / 하위 에이전트 작업)으로 내려간다.
  - OMH v06: 큰 'OMP 기본 기능' 위에 얇은 파란 띠 'omh-rigorous, 내 업무 절차'.
- **아래 띠 (작성자 경험):** '며칠 동안 v05까지 만들었는데, 상당 부분은 이미 기본 기능이었음', 'v06에는 필요한 절차만 얇게. 하네스가 사라진 게 아니라 내가 덧붙일 부분이 줄어듦'.
- **화면에 넣지 않은 것:** data_inspect, data_compare 이름, 크기, 줄 수, 성능.
- **노트:** 작성자의 전환 경험과 공식 README의 일반 기능을 나누어 적고, 맺음말과 연결했다. 근거는 [전환 경험 자료](../references/omh-omp-evolution-v01.md)다.

## 검사

- **v20 검사:**
  - 15쪽이 유일한 case-detail(원래 번호 omh-evolution)이고, 사례는 5개.
  - 제목과 세 단계 문구가 있음. 업무 도구 이름과 측정 수치가 화면에 없음.
  - 직접 덧붙인 층의 크기: v05는 바탕보다 크고, OMP 단계는 점선이고, v06은 v05의 3분의 1 미만이며 바탕의 4분의 1 미만임.
  - 노트에 출처가 있음.
  - v19의 45장이 한 장씩 밀린 자리에서, 쪽 표기를 빼면 화면이 같음.
- **기존 검사:** 참고 화면, Grokbot, 참고 C, 맺음말을 고정된 쪽 번호 대신 manifest에서 찾는다. 각 판의 기대값(v16~v19의 쪽 지도, v19의 v18 대조)은 그 판에만 그대로 적용한다. v20의 쪽 지도는 21, 22, 29, 30, 35, 45다.
- **대기와 인쇄:** 화면을 바꿀 때마다 글꼴 준비와 220ms를 기다린다. 인쇄 전에는 글꼴 준비, 두 번의 화면 갱신, 250ms를 기다린다. PDF는 46쪽이다.

- 최종 문구 검수에서 새 약어를 화면만 봐도 알 수 있도록 가운데 제목에 OMP의 풀네임(Oh My Pi)을 함께 표시했다.
