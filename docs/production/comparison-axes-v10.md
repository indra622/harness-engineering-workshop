# v10 비교 축 변경 메모

v10은 v09의 44장을 그대로 두고 14쪽, 15쪽, 16쪽만 바꿨다. 다른 41장은 v09와 같다. 특히 9쪽(클식이, 업무 난이도 자동 판단, 게이트웨이의 채널, 세션, 스케줄러, 직접 처리와 워커에게 위임, 같은 코디네이터의 결과 확인)은 손대지 않았다.

## 14쪽: OpenCode 순정과 OMH 통합 구성

- **사용자 요청:** "14페이지는 opencode 순정 vs (omo+omh)로, 설명은 omh가 omo를 포함한 것처럼."
- **바뀐 비교 축:**
  - 이전(v06부터 v09까지): OpenCode와 OMO를 양쪽 공통 기반으로 두고, OMH가 더한 도구와 절차가 있을 때와 없을 때를 비교했다.
  - v10: OpenCode 순정과, OMO까지 묶은 OMH 통합 구성을 비교한다. 이전 비교 축은 이 판에서 대체된다.
- **그림 구성:**
  - 오른쪽 OMH 경계 안에 세 칸을 둔다: OMO(역할 협업과 작업 흐름), 업무 도구(data_inspect, data_compare), 작업 절차(omh-rigorous).
  - 화면에는 'OMO + 업무 도구 + 작업 절차'와 'OMO의 역할 구성까지 묶은 OMH'를 적었다.
  - 왼쪽은 범용 코딩 에이전트 환경이다. 파일 읽기, 쓰기, 명령 실행, 계획과 확인을 할 수 있고, 같은 일을 그때그때 스크립트와 절차를 준비해 해낸다.
- **유지한 사실:**
  - 같은 일과 같은 빈 값 규칙을 쓴다. data_inspect는 행 값을 내보이지 않고, data_compare는 자동 병합하지 않는다.
  - 모델은 같고 학습하지 않았다. 사람이 규칙과 결과 수용을 정한다. 속도나 품질 점수는 없다.
  - 역할마다 다른 모델, 별도 상주 프로그램, 자동 품질 보장은 말하지 않는다.
- **근거:**
  - OMH 통합 v04 참고 문서(구성과 조건, 역할, 도구)를 따랐다. 로컬 보관 자료이며 이 저장소에 없다. 패키지를 실행하거나 설치하지 않았다.
  - 확인한 관계: OMO의 역할 협업과 작업 흐름, 원래 플러그인과 실행기, 의존성이 OMH 데이터 도구와 한 통합 패키지에 들어 있다.
  - OpenCode와 Python은 미리 설치해야 하는 전제이고 패키지에 들어 있지 않다.
  - OMO 역할은 모두 같은 모델을 쓴다.
- **노트:** v10 기획(S11) 발췌 앞에 '정정' 문단을 두었다. 발췌와 이전 판의 비교 축은 기록이라고 밝혀, 원래 출처가 지금의 요청을 덮어쓰지 않게 했다.

## 15쪽: AS-IS Superpowers, TO-BE pstack

- **사용자 요청:** "15페이지는 슈퍼파워가 as-is고 pstack이 to-be야."
- **그림 구성:**
  - 위에 AS-IS Superpowers, 아래에 TO-BE pstack을 두고, 그 사이에 큰 전환 화살표와 '작업별 절차 선택으로'을 넣었다.
  - 아래 띠는 바뀌는 초점을 적고, 둘 다 계획, 위임, 검토, 테스트를 할 수 있다는 점을 짧게 밝힌다.
- **말하지 않는 것:** 성숙도 단계표, 제품 순위, 실제 조직의 전환 완료, 측정한 속도나 정확도.
- **출처 사실과 고정 커밋:** 비교 자료 v01 그대로다. 관점과 OMH 관계는 [비교 자료 v02](../references/pstack-superpowers-comparison-v02.md)에 정리했다.

## 16쪽: 맞춤 정리

- 왼쪽 두 상자를 'TO-BE pstack에서 가져올 것'과 'AS-IS Superpowers (비교 참고)'로 바꿨다.
- Superpowers에서 가운데로 가는 선은 점선으로 바꿨다. 지금 방식의 참고이지 OMH 계보가 아니라는 뜻이다.
- 오른쪽 OMH 상자는 '같음: 설정된 모델 하나', '포함: OMO 역할 구성'으로 14쪽과 맞췄다.
- 노트의 OMH 연결과 Superpowers 문단을 같은 방향으로 고쳤다.
