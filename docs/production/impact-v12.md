# v12 변경 메모: 14쪽 임팩트, 15쪽 읽는 순서, 27쪽 흐름 맞춤

v12는 v11의 44장에서 14쪽, 15쪽, 27쪽만 바꿨다. 2쪽과 16쪽을 포함한 다른 41장은 v11과 같다.

## 14쪽: 행 수는 그대로, 빠진 ID까지 찾아내기

- **사용자 요청:** OMH 설명의 임팩트가 약함. 순정보다 OMH를 써야 하는 이유를 분명한 예시로. 오픈코드가 비효율적으로 하거나 못 하는 것을 OMH가 효율적으로, 잘 한다는 것을 보여 줄 것.
- **장면:** 요청은 'CSV 빈 amount만 0으로, 행 추가와 삭제는 0건'.
  - 첫 결과는 행 3 → 3, 빈 값 1 → 0이라 겉보기엔 통과다.
  - id 기준 data_compare가 left_only 1, right_only 1을 찾는다(원래 ID 하나가 빠지고 새 ID 하나가 생김).
  - 검토 기준(추가, 삭제 0건)에 걸려 완료 보고 전에 되돌린다.
  - 수정 결과는 left_only 0, right_only 0이고 amount 1행만 바뀐다.
- **대비:** 왼쪽 OpenCode 순정은 전용 도구가 없으면 빈 값 점검 스크립트, id 비교 코드, 검토 기준 연결을 직접 준비한다. 오른쪽 OMH 통합 구성은 OMO(역할 분담, 검토), data_inspect와 data_compare, omh-rigorous를 미리 묶어 다시 쓴다. OMO는 OMH 경계 안에 있다.
- **실제와 설명용의 경계:**
  - 실제: [examples/omh-v12/](../../examples/omh-v12/README.md)의 합성 CSV에 OMH 통합 v04 엔진의 data_inspect, data_compare를 실제로 실행한 개수. csv 모듈로 따로 센 값과 같다.
  - 설명용: 첫 결과 파일은 손으로 만든 합성 데이터이고, 역할 분담과 검토, 되돌림 흐름은 설명용이다.
  - 도구의 ok는 호출 성공일 뿐 업무 기준 통과가 아니다. 값은 반환하지 않아 화면에는 ID 값 대신 개수만 있다.
- **말하지 않는 것:** 순정이 못 한다거나 늘 실패한다는 것, 속도나 정확도 수치, 오류 없음 보장, 자동으로 막는 관문, 질문 횟수가 늘 준다는 것. 이미 만들어 둔 스크립트가 있으면 순정에서도 다시 쓸 수 있다는 점은 노트에 적었다.

## 15쪽: 기본기는 모델에, 업무 기준과 위임은 하네스에

- **사용자 요청:** 강조점이 맨 아래라 메시지가 약함. 흐름을 따르려면 Superpowers와 pstack의 위치가 바뀌어야 함.
- **바뀐 것:**
  - v11 아래 띠의 요지를 제목으로 올렸다.
  - 그림은 위에서 아래로 읽는다. 먼저 Superpowers의 실행 기본기, 짧은 연결 화살표와 '그 위에서, 이 일에 맞게', 이어서 pstack의 다음 초점을 파란색으로 둔다.
  - '업무 운영 층' 표현은 '다음 초점'으로 바꿨다.
  - 아래 띠는 겹치는 부분(두 묶음 모두 계획, 위임, 검토, 테스트를 갖춤)으로 바꿨다.
- **그대로인 것:**
  - AS-IS, TO-BE 표기 없음.
  - Superpowers는 잘 만든 기본 절차라는 관점.
  - 노트의 사실과 해석 구분과 세 출처.
  - [비교 자료 v03](../references/pstack-superpowers-comparison-v03.md)의 사실 경계. 위아래는 설명 순서이지 순위나 전환 단계가 아니다.

## 27쪽: 2쪽과 같은 일곱 단계

- **사용자 요청:** 27쪽보다 맨 앞에 나온 AI교양 흐름이 더 적절함. 앞부분에 맞춰 27쪽도 수정할 것.
- **바뀐 것:**
  - 가운데 흐름을 2쪽과 같은 일곱 단계, 같은 색, 같은 역할 라벨로 바꿨다(작가의 몫, AI와 함께, 작가가 결정, 확정 뒤 정해진 절차).
  - 질문에 대한 답 한 줄('삽화는 4단계 작가 확정 뒤에, 확정 전이면 3단계로 돌아가 수정')과 '공개 발행은 이 흐름 밖' 표시를 넣었다.
  - 둘레의 규칙, 컨텍스트, 도구, 상태, 검증 다섯 칸은 그대로 두었다. 규칙 칸의 '원문 보존'은 '초고 v01 보존'으로 바꿨다.
- **노트:** v10 발췌(S21) 앞에 정정을 두어, 네 단계 압축 흐름을 대체했다는 점과 '원문'이 작가가 직접 쓴 초고 v01이라는 점을 밝혔다.
- **2쪽:** 바이트 단위로 v11과 같다.

## 검사

- **v10, v11 검사:** 각 판에만 적용한다.
  - 14쪽 라벨 묶음은 v10과 v11에 적용한다.
  - 15쪽 v11 제목과 위아래 층 검사는 v11에만 적용한다.
- **v12 검사:**
  - 14쪽: 장면 네 칸의 순서, 화면 개수와 기록된 실제 실행 결과의 일치, 절대 표현과 속도 주장 없음, OMO가 OMH 안에 있음.
  - 15쪽: 제목이 요지 문장임, 제목이 두 줄보다 위에 있음, Superpowers가 pstack보다 위에 있음, pstack 상자만 파란색.
  - 15쪽과 16쪽: AS-IS, TO-BE 없음.
  - 27쪽: 일곱 단계의 글자, 색, 역할이 2쪽과 같음. 원래 번호 25, 사례 AI교양, 출처 S21 유지.
  - 27쪽 노트: 정정이 발췌보다 앞에 있음.

## 번호와 보존

- 44장 구성(용어 25, 사례 5, 참고 2, 쉬는 시간 28쪽, CEO Agent 33쪽, 본문으로 17쪽)은 그대로다. 강의 시간 표기는 없다.
- v02부터 v11까지의 내보낸 결과는 바뀌지 않았고, 다시 빌드해도 같은 바이트가 나온다.
