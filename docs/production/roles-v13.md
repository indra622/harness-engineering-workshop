# v13 변경 메모: 14쪽을 역할 흐름으로

v13은 v12의 44장에서 14쪽 화면과 노트만 바꿨다. 15쪽과 27쪽을 포함한 다른 43장은 v12와 같다.

## 사용자 요청

- CSV, amount 같은 기술 예시와 OMO의 역할 분담이 잘 이해되지 않는다.
- 쉬운 요청과 역할 흐름으로 다시 보여 달라는 방향을 승인했다.

## 14쪽: 빈칸만 채우랬는데, 번호까지 바뀌었다면?

- **요청:** '표의 금액 빈칸만 0으로 채워 줘. 번호와 상품은 그대로'. 화면에는 CSV, amount, left_only 같은 말을 쓰지 않는다.
- **역할 흐름:** OMH 통합 구성 경계 안에 OMO 역할 협업 경계를 두고, 그 안에 세 역할을 둔다.
  - 총괄은 기준(번호, 상품 유지, 줄 추가와 삭제 0)을 정하고 맡긴다.
  - 작업 담당은 표를 고친다. 줄 수 3 → 3, 빈칸 1 → 0이라 겉보기엔 끝났다.
  - 검토 담당은 원본과 결과를 비교한다. '금액 빈칸 → 0'은 요청한 변경, '상품 A 번호 0 → 3'은 요청 밖 변경이다. 준비된 비교 도구(data_compare)는 검토 담당 옆의 보조 표시로만 둔다.
- **연결 여섯 개:**
  - 맡김(총괄 → 작업)
  - 고친 표(작업 → 총괄)
  - 다시 고침(총괄 → 작업, 호박색 점선)
  - 원본과 결과(총괄 → 검토)
  - 검토 결과(검토 → 총괄)
  - 검토 통과 뒤 보고(총괄 → 요청)
  - 처음과 다시 확인은 같은 화살표를 함께 쓴다. 작업 담당이 검토 담당이나 요청자에게 바로 가는 선은 없다.
- **왼쪽 OpenCode 순정:** 전용 도구가 없으면 비교 코드, 검토 기준, 다시 맡기는 연결을 직접 준비한다. 할 수는 있다는 점을 화면에 적었고, 이미 만든 스크립트를 다시 쓸 수 있다는 점은 노트에 적었다.

## 사실 경계

- **실제:** 바뀐 내용은 v12와 같은 합성 예시(examples/omh-v12/)에 data_compare를 실제로 실행한 결과다.
  - 첫 결과: 원본에만 있는 번호 1개, 결과에만 있는 번호 1개.
  - 수정 결과: 둘 다 0.
  - 비교 도구는 의도한 금액 변경도 차이로 보고하므로, 기준은 '차이 0'이 아니라 '번호 추가, 삭제 0'이다.
- **설명용:** 역할 흐름 전체는 설명용이며 실제 에이전트 실행 기록이 아니다. 화면 각주와 노트에 밝혔다.
- **역할 이름:** 노트에서 OMH 통합 v04 참고 문서의 역할(orchestrator, fixer, oracle)에 빗대어 설명한다. 이 세 역할 흐름이 늘 고정돼 있다거나, 검토 역할이 도구를 직접 실행한다고 말하지 않는다.
- **전제:** 모든 역할은 같은 모델을 쓰고 추가 학습은 없다.

## 검사

- **v12 검사:** 14쪽 라벨 묶음과 장면 네 칸 순서는 v12에만 적용한다.
- **v13 검사:**
  - 14쪽 쉬운 요청 문구와 역할 이름이 있음. CSV, amount, left_only, right_only, value_changed가 화면에 없음.
  - 세 역할이 OMO 안, OMO가 OMH 안에 있음.
  - 연결 여섯 개의 보내는 쪽, 받는 쪽, 종류, 순서가 맞음. 각 화살표가 두 역할 상자의 가장자리에 붙어 있음. 다시 고침은 점선임.
  - 보고는 총괄에서 요청 띠로만 나감. 총괄을 건너뛰는 연결이 없음.
  - 화면의 변경 내용이 기록된 실제 실행 결과와 맞음.
- **인쇄:** v12의 인쇄 대기(글꼴 준비, 두 번의 화면 갱신, 250ms)와 PDF 제목 지정은 v13에도 그대로 적용된다.
