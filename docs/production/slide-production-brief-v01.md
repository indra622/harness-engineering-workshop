# 하네스 엔지니어링 워크샵 슬라이드 제작 브리프 v01

이 문서는 제작 지침서다. 실제 덱, PDF, HTML, 이미지, 발표 파일은 만들지 않았다. 원천은 [슬라이드 내용 정의 v10](../plans/slide-content-plan-v10.md)이며, 충돌하면 v10이 우선한다. 권장 형식(편집 가능한 16:9 덱, PDF, 발표자 노트)은 제안이며 확정되거나 요청된 형식이 아니다.

## 1. 목적과 경계

- 목적: 설계자나 발표자가 v10을 보고 슬라이드를 만들 때 추측하지 않도록 화면, 도식, 진행, 노트, 자료, 검수 기준을 정한다.
- 범위: 35장, 120분. 용어 25개(각 3분, 합계 75분), 도입 5분, 휴식 10분, 사례 25분(OpenClaw 5, OMH 5, Grokbot 3, AI교양 5, CEO Agent 3, 종합 4), 질의응답 5분.
- 참가자 실습은 0분이다. 설치, 계정 준비, 파일 준비, 강제 참여를 요구하지 않는다.
- 연구 자료와 로컬 근거는 재게시하지 않는다. 논리 경로만 적는다. 로컬 원본은 공개 저장소에 없다.
- 청중은 제안이다: 업무 전문가이며 코딩 경험은 다양할 수 있다. 방 크기, 장소, 장비, 브랜딩은 확정되지 않았으며 이 문서에서 정하지 않았다.

## 2. 편집 방향

- 서사: AI교양 완료 장면으로 열고, 개념 몇 개를 익힌 뒤 사례를 읽고, 장면으로 돌아오는 순서다. 개념과 사례는 v10 순서대로 번갈아 놓는다. 긴 정의 목록은 만들지 않는다.
- 용어 슬라이드 한 장의 흐름: 장면과 질문, 정의와 상세 설명, 같은 장면에 다시 적용, 이웃 개념과 구분, 짧은 확인. 장면 20초에서 30초, 질문 5초에서 10초를 3분 안에 넣고 추가 시간은 쓰지 않는다.
- 화면과 노트를 나눈다. 화면에는 용어 제목, 짧은 정의 한 문장, 중심 시각 하나, 라벨 몇 개만 둔다. 상세 설명, 백업 CSV 예시, 조건과 한계는 발표자 노트에 둔다. 백업 예시는 화면에 올리지 않는다.
- 애니메이션은 필수가 아니다. 한 장 안의 단계는 정적 최종 상태에서도 라벨로 순서를 알 수 있게 한다.
- 강제 참여는 없다. 질문에 모두 답할 필요가 없다.

## 3. 시각 방향 (초안, 승인된 브랜드 아님)

- 비율과 바탕: 16:9, 밝은 중립 바탕 #F7F7F4, 본문 텍스트 #1F2328.
- 강조: 주 강조 #2B5FA8 하나, 경고 #B45309 하나. 색은 의미를 혼자 전달하지 않는다. 경고와 게이트는 굵은 테두리나 라벨을 함께 쓴다.
- 의미 역할: 주 강조는 현재 대상과 전환 조건, 경고는 사람의 확정 게이트나 주의, 회색 점선은 범위 밖이나 실행하지 않은 것이다.
- 글꼴: 한글 산세리프 한 가지를 기본으로 하고 시스템 한글 폴백을 둔다. 특정 글꼴 설치는 요구하지 않는다.
- 크기: 제목 36pt에서 40pt, 본문 24pt에서 28pt, 도식 라벨 최소 20pt, 출처 표기만 16pt 이상. CSS px가 아니라 pt로 적는다.
- 배치: 좌우 여백은 넉넉히 두고 격자에 맞춘다. 한 화면 라벨은 최대 6개, 도식 노드는 최대 7개를 목표로 한다(제안).
- 시각 문법은 다양하게 한다: 요청과 결과, 과정 루프, 범위 컨테이너, 전후 비교, 증거 패널, 구조도. 같은 카드 틀을 스물다섯 번 반복하지 않는다.
- 금지: 장식용 그라데이션 카드, 아이콘 벽, AI 로봇 이미지, 스톡 이미지.
- 접근성: 대비 비율은 계산하지 않았다. WCAG 통과를 주장하지 않는다.
- 형식 참고: `reference/DESIGN.md-format.md`는 참고만 한다. 이번 작업에서 DESIGN.md는 만들지 않았다.

## 4. 35장 제작 맵

각 슬라이드는 v10의 제목과 시간을 그대로 쓴다. 여섯 항목은 짧게 쓴다.

### S1. 시작: 완성된 업무 한 건 (0분부터 2분까지, 2분)

**화면 핵심 문장:** 완성된 AI교양 한 건은 어떤 단계를 거쳤나?

**레이아웃과 도식:** 상단 장면 한 줄. 가운데 가로 다섯 칸(원문, 수정, 최종 확정 굵은 게이트, 삽화와 보관, 비공개 초안과 재열람). 오른쪽 끝 회색 점선 '공개 발행: 범위 밖'.

**공개 순서와 진행:** 장면 20초, 질문 5초에서 10초. 답은 S34에서 돌아와 공개한다. 목표 다섯 개는 말로 전한다.

**발표자 노트:** v10 S1 장면과 학습 목표 다섯 개. 참가자는 실습하지 않고 듣고 질문만 한다. 실제 화면, 계정, 공개 발행은 보여 주지 않는다.

**필요 자료와 준비 상태:** v10 S1 텍스트 준비됨. 다섯 칸 도식은 AS-10으로 미제작.

**제작 검수 포인트:** 공개 발행이나 자동 게시가 암시되지 않는가. 실제 화면 캡처가 없는가.

### S2. 로드맵과 예시 장면 (2분부터 5분까지, 3분)

**화면 핵심 문장:** 오늘은 개념과 사례를 번갈아 본다.

**레이아웃과 도식:** 상단에 다섯 사례 이정표(OpenClaw, OMH, Grokbot, AI교양, CEO Agent)를 놓고 각 이정표 위에 바로 앞의 개념 묶음을 붙인다. AI교양과 CEO Agent 사이에 휴식을 표시한다. 개념 전체 뒤에 사례 전체가 오는 도식은 쓰지 않는다. 하단 장면 칩 다섯 개(회의 준비, 메일 초안 발송 없음, 문서 검토, 파일 찾기와 인계, 주간 요약).

**공개 순서와 진행:** 로드맵을 20초 말한다. 칩은 가리키기만 하고 설명하지 않는다.

**발표자 노트:** v10 S2 로드맵과 2.1~2.4(가상 CSV, 참가자 전제, 확인 기준, AI교양 흐름). 칩은 가상 초안이다.

**필요 자료와 준비 상태:** v10 S2 텍스트 준비됨. 칩은 텍스트로만 만든다.

**제작 검수 포인트:** 칩이 다섯 개인가. 참가자 준비 요구가 없는가.

### S3. 모델 (5분부터 8분까지, 3분)

**화면 핵심 문장:** 모델은 입력으로 다음 출력을 계산한다.

**레이아웃과 도식:** 왼쪽 요청 A(회의 준비해 줘)와 요청 B(안건 세 줄 추가), 가운데 같은 모델과 '여기서 파일은 열리지 않음' 주석, 오른쪽 각각의 가상 결과(일반 목록, 안건 반영 목록).

**공개 순서와 진행:** 장면 20초, 질문 '안건을 모르고도 그럴듯한 준비안이 나올까?' 5초에서 10초. 정의 공개, 출력 비교, 에이전트와 구분 순서.

**발표자 노트:** v10 S3 정의, 상세 설명 세 항목, 헷갈림을 쓴다. 출력은 가상 예시다. 백업 CSV 예시는 노트에만 둔다.

**필요 자료와 준비 상태:** AS-02 요청과 결과 쌍.

**제작 검수 포인트:** 출력이 실제 답처럼 보이지 않는가(가상 표시). 모델이 파일을 연다고 암시하지 않는가.

### S4. 에이전트 (8분부터 11분까지, 3분)

**화면 핵심 문장:** 목표, 행동, 결과 확인, 종료 조건이 도는 구성이다.

**레이아웃과 도식:** 상단에 목표를 고정하고 원형 루프 네 노드(모델 판단, 도구 실행, 결과 확인, 종료 조건)를 둔다. 발송은 루프 밖 회색 점선.

**공개 순서와 진행:** 장면 20초, 질문 '쓰고 확인하고 고치는 순환이면 에이전트에 가까울까?' 5초에서 10초. 루프를 그린 뒤 메일 목표를 채운다.

**발표자 노트:** v10 S4 정의, 루프, 종료 조건, 서브에이전트와 구분. 메일은 초안만, 발송 없음. 응답 횟수만으로 에이전트 여부를 판단하지 않는다. 도구 결과에 따라 후속 행동과 종료를 정할 수 있는 구조인지 본다.

**필요 자료와 준비 상태:** AS-03 과정 루프.

**제작 검수 포인트:** 발송이 루프 밖에 있는가. 여러 에이전트가 필요하다는 인상이 없는가.

### S5. 런타임 (11분부터 14분까지, 3분)

**화면 핵심 문장:** 모델은 요청만 만들고, 런타임이 실행해 결과를 돌려준다.

**레이아웃과 도식:** 상단 모델(read_file 요청 한 줄), 가운데 런타임 띠(권한 확인, 실행), 하단 파일. 결과 화살표가 위로 돌아온다.

**공개 순서와 진행:** 장면 20초, 질문 'AI 모델이 파일을 직접 열까?' 5초에서 10초. 요청, 권한, 결과 순서로 짚는다.

**발표자 노트:** v10 S5 정의와 네 문단. 파일 없음 오류는 가상이다. 언어 실행 환경과 구분하는 주석을 유지한다.

**필요 자료와 준비 상태:** AS-03 과정 루프(띠 변형). 대표 검수 장.

**제작 검수 포인트:** 런타임이 언어 실행 환경으로 읽히지 않는가. 모델이 파일을 여는 것처럼 보이지 않는가.

### S6. 하네스 (14분부터 17분까지, 3분)

**화면 핵심 문장:** 컨텍스트, 도구, 실행 위치, 상태, 검증을 묶은 작업 틀이다.

**레이아웃과 도식:** 가운데 원 하나, 둘레 다섯 칸(컨텍스트, 도구, 실행 위치, 상태, 검증). 원 밖에 모델 상자 하나. 칸 안 파일명은 가상.

**공개 순서와 진행:** 장면 20초, 질문 '체크리스트 파일을 넣으면 검토 틀이 갖춰질까?' 5초에서 10초. 다섯 칸을 하나씩 채운다.

**발표자 노트:** v10 S6 정의, 세 항목, 헷갈림(오케스트레이션, 런타임). 하네스 범위는 제품마다 다르다.

**필요 자료와 준비 상태:** AS-04 범위 컨테이너.

**제작 검수 포인트:** 다섯 칸 모양이 같은 카드 틀이 아닌가. 칸 이름이 용어와 맞는가.

### S7. OpenClaw 구조 (17분부터 22분까지, 5분)

**화면 핵심 문장:** 요청은 게이트웨이와 세션을 거쳐 코디네이터가 직접 처리하거나 워커에 맡긴다.

**레이아웃과 도식:** 위에서 아래로 구조도: 요청, 게이트웨이와 세션, 코디네이터, 분기(직접 도구, 원격 워커), 프로젝트 파일, 부모 검증, 답장. 네 개념만 강조.

**공개 순서와 진행:** 장면 '보고서 검증 요청' 20초, 질문 '받는 쪽, 맡기는 쪽, 확인하는 쪽은?' 5초에서 10초. 강조한 네 개념만 찾는다. 워커와 세션은 S23, S24에서 다룬다고 약속한다.

**발표자 노트:** v10 S7 본문을 줄인다. 위임 기준은 운영 지침이며 자동 라우터가 아니다. 실시간 상태는 확인하지 않았다.

**필요 자료와 준비 상태:** AS-07 구조도. 텍스트 준비됨, 도식 미제작.

**제작 검수 포인트:** 기능 목록처럼 보이지 않는가. 강조가 네 개념에만 있는가.

### S8. 오케스트레이션 (22분부터 25분까지, 3분)

**화면 핵심 문장:** 누가 언제 무엇을 맡을지 정하는 조율이다.

**레이아웃과 도식:** 세로 레인 세 개(기획, 실행, 검토), 가로축은 시간. 칸마다 산출물, 전환 화살표에 조건.

**공개 순서와 진행:** 장면 20초, 질문 '맡는 사람이 없으면 같은 일을 두 번 할까?' 5초에서 10초. 레인을 채운 뒤 역할 분리가 독립 검토는 아니라고 짚는다.

**발표자 노트:** v10 S8 정의, 순서와 역할과 전환 조건, 여러 실행 주체가 필요하지 않다는 점, 헷갈림(워크플로우).

**필요 자료와 준비 상태:** AS-03 과정 루프(레인 변형).

**제작 검수 포인트:** 한 사람이 세 역할을 맡은 경우도 그려져 있는가. 독립 검토 주장이 없는가.

### S9. 도구 (25분부터 28분까지, 3분)

**화면 핵심 문장:** 모델이 요청하고 런타임이 실행하는, 이름과 입력과 결과 형식이 있는 기능이다.

**레이아웃과 도식:** 좌측 도구 카드(name, input, output). 우측 호출 한 줄과 결과 한 줄. 하단 칩: 절차는 도구가 아니다.

**공개 순서와 진행:** 장면 20초, 질문 '목록 기능과 찾는 순서 메모 중 무엇이 실행될까?' 5초에서 10초. 카드와 메모를 나란히 보여 준다.

**발표자 노트:** v10 S9 정의, 세 항목, 헷갈림(스킬, MCP). 호출 예시는 가상이다.

**필요 자료와 준비 상태:** AS-02 요청과 결과 쌍.

**제작 검수 포인트:** 카드 틀이 다른 장에 반복되지 않는가.

### S10. 스킬 (28분부터 31분까지, 3분)

**화면 핵심 문장:** 절차, 입력과 출력 규칙, 자원을 묶은 재사용 지침이다.

## 5. 자산 목록 (재사용 중심, 12개)

35개의 새 그림을 만들지 않고 같은 구조를 재사용한다. 원고 있음과 시각 준비 완료는 다르다. 아래 시각은 아직 렌더링하지 않았다.

- AS-01 장면 카드 틀 (P0): 장면과 질문을 한 번 쓰는 공통 틀. 원고 있음, 시각 미제작. 대상 S1, S2, 용어 슬라이드 전부.

- AS-04 범위 컨테이너 (P1): 큰 상자와 안쪽 칸, 점선 경계. 원고 있음. 대상 S6, S13, S14, S20, S23, S24, S31, S32, S33.
- AS-05 전후 비교 패널 (P1): 두 열 전후 비교. 원고 있음. 대상 제작 시 선택.
- AS-06 증거 패널 (P0): 항목, 확인 방법, 결과 기록. 원고 있음. 대상 S29, S30.

- AS-08 세 축 도식 (P0): 실제 제약, 바꾼 것, 증거와 한계. 원고 있음. 대상 S11.
- AS-09 CSV 흐름 (P1, 가상 예시): 구조 점검, 변경, 키 기준 비교 세 칸. 원고 있음. 대상 S11. 실제 데이터 없음.
- AS-10 AI교양 단계 도식 (P0): 다섯 단계와 확정 다이아몬드. 원고 있음. 대상 S1, S21, S27, S28, S34.
- AS-11 페르소나 두 줄 도식 (P0): 윗줄 연구 근거, 아랫줄 과업 선택. 원고 있음. 대상 S26.
- AS-12 확인 질문 카드 (P1): 질문과 모범 답안 자리. 원고 있음. 대상 용어 슬라이드 전부.

원고 있음은 v10 텍스트에서 가져올 수 있다는 뜻이다. 자료는 논리 경로로만 가리킨다. 실제 내부 자료, 계정, 화면은 준비 목록에 넣지 않았다.

## 6. 제작 순서와 넘김 기준

1. 대표 여섯 장을 먼저 만든다: S1, S5, S11, S17, S26, S34. 이 시안은 아직 만들지 않았다. 
2. 대표 여섯 장을 보고 자산 목록을 확정한 뒤 나머지 29장을 만든다.
3. 썸네일과 프로젝션 가독성을 확인한다. 제목, 카드, 표 대신 목록, 도식, 마감 장을 본다.
4. PDF를 만들어 편집본과 비교한다.
5. 발표자 노트와 v10의 일치를 확인한다.

Google Slides를 고르게 되면 텍스트 상자의 contentAlignment를 MIDDLE로 둔다. 의도된 정렬이 있으면 예외로 한다. 썸네일로 제목, 카드, 표, 도식, 마감 장을 확인한다. 지금은 Google 계정이나 API가 필요하지 않다.

넘김 기준은 다음과 같다. 35개 제목과 시간이 v10과 같은가. 용어 25개가 개별 장으로 있는가. 사례가 S7, S11, S15, S21, S26 자리에 있는가. 실습 요구가 없는가. 공개 범위가 맞는가. 라벨과 출처가 보존되었는가.

미검증: 서사의 효과, 실제 방의 가독성, 노트 기준의 발표 시간은 확인하지 않았다. "지루하지 않다"는 결과를 약속하지 않는다.
