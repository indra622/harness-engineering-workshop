# v22 변경 메모: 용어 LLM wiki 추가

v22는 v21(46장)의 메모리(28쪽) 바로 뒤 29쪽에 용어 'LLM wiki' 한 장을 넣어 47장이 됐다. 참고 화면이 아니라 보통 용어 화면이며, OKF도 이 장 안에서 설명한다. 용어는 26개가 됐고, 사례 5, 참고 3, 사례 이어서 1, 마지막 맺음말은 그대로다. v21의 15쪽 OKF 한 줄도 그대로 두었다.

## 사용자 요청 (2026-10-22)

- LLM wiki는 참고 화면이 아니라 용어 하나다.
- OKF는 같은 장에서 설명한다.
- 메모리 다음에 둔다.

## 29쪽 화면

- **머리:**
  - 머리말: '3장 용어 16 / 26'
  - 용어: 'LLM wiki'
  - 정의: 'LLM과 함께 지식을 정리하고 연결해, 필요할 때 다시 찾아 쓰는 방식'
- **장면:** '지난 AI교양 글에서 정리한 개념을 새 글에도 쓰고 싶다.' / '저장해 둔 노트, 새 세션이 저절로 떠올릴까?'
- **도식 '쌓아 둔 기록을, 다음 작업의 재료로':** AI교양 예시 네 단계.
  - 1 원문 보존: 내가 쓴 원고, 참고 자료는 따로 둠
  - 2 정리와 연결: 개념 노트와 출처, 관련 글과 인덱스
  - 3 관련 노트 찾고 읽기: 새 글 주제로 검색, 실제 내용을 읽음. 파란색으로 강조함.
  - 4 다음 글에 재사용: 이전 관점을 가져옴, 근거는 사람이 다시 확인
- **저장과 읽기를 나눈 띠:**
  - 1, 2 단계 아래: '파일로 남긴 위키 (예: Obsidian)'
  - 3, 4 단계 아래: '이번 작업의 컨텍스트로 읽어 옴'
  - 저장해 두면 저절로 기억된다는 식의 화살표는 그리지 않았다.
- **아래 두 줄:**
  - 'LLM wiki는 정리하고 쓰는 방식, OKF(Open Knowledge Format)는 출처와 상태를 적는 형식'. OKF는 여기서 처음 나오므로 풀네임을 한 번 적었다.
  - '저장만으로 기억되는 건 아님. 필요한 노트를 찾아 읽는 단계까지.'
- **예시 성격:** 노트 이름과 내용은 만든 예시다. 실제 개인 노트나 화면, 저장 경로는 쓰지 않았다.

## 노트

- **담은 내용:** 정의, AI교양 예시, 저장과 읽기의 구분(앞의 메모리와 연결), LLM wiki와 OKF의 구분, 운영 근거, 말하지 않는 것, 확인 질문과 모범 답안.
- **운영 근거:** '클식이 지식 정리 운영 방식, 2026-10-22 확인'을 일반화해 적었다.
  - 원문을 따로 보존한다.
  - 다시 쓸 노트는 AI와 함께 검토하며 출처, 의미 있는 연결, 인덱스를 달아 정리한다.
  - 노트 버전을 남기고, 사실과 해석과 열린 질문을 나눈다.
  - 작업할 때는 실제 파일을 찾아 읽는다.
  - 모든 문서가 자동으로 노트가 되거나 모든 대화가 보관된다고 말하지 않는다.
- **OKF 출처:** [OKF v0.2 명세, 고정 커밋 ad30107](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/ad30107c31c06aec8a7d5636e0d1058118604e6f/SPEC.md)
  - Markdown 본문과 YAML 머리말로 출처, 상태 같은 메타데이터와 링크를 적는 형식이다.
  - 검색기, 실행 방식, 자동 기억 갱신은 정하지 않는다.
- **말하지 않는 것:** 모델 학습, 빠짐없는 기억, 성능 향상 보장, 모두에게 필요하다는 주장. LLM wiki는 제품명이나 업계 표준이 아니라 이 발표에서 쓰는 이름이다.

## 함께 바뀐 곳

- **용어 번호:**
  - 모든 용어 머리말이 'n / 26'이 됐다.
  - 메모리 뒤 용어(세션부터 리모트 컨트롤까지)는 번호가 하나씩 늘었다(17~26).
  - 이전 판은 25개 그대로 다시 빌드된다.
- **표지와 길잡이:**
  - 표지: '용어 26개와 사례 5개로…'. 표지 노트와 페이지 설명도 26개로 맞췄다.
  - 3쪽 오늘의 길: 3장 용어에 LLM wiki를 더했다.
  - 23쪽 3장 표지: 경로를 일곱 정거장으로 다시 그렸다(LLM wiki, '정리해 다시 찾기'). 목표 문구에 '다시 찾아 쓰기'를 더했고, 노트의 순서도 맞췄다.
  - 참고 A, C 노트: '본문(26개 용어와 다섯 사례)'.
- **쪽 번호:**
  - 28쪽 뒤는 한 장씩 밀렸다: AI교양 30, 쉬는 시간 31, CEO Agent 36, 종합 45, 질의응답 46, 맺음말 47.
  - 2쪽 노트를 'AI교양 사례(30번)', '워크플로우(38번)'로, AI교양 정정의 쪽 표기를 'v22부터 30쪽'으로 바꿨다.
  - 질의응답 3장 목록에 '29 LLM wiki'를 넣고, 그 뒤 번호를 하나씩 늘렸다.
  - 질의응답 노트에는 발췌의 '용어 25개'가 이전 구성 기준이라는 정정을 두었다.
- **그대로인 것:** 참고 A, B, C의 위치(16, 17, 22)와 건너뛰기 링크(18, 23쪽).

## 검사

- **v22 검사:**
  - 29쪽 LLM wiki가 메모리 바로 뒤의 보통 용어임(16 / 26, 원래 번호 llm-wiki, 참고 표시와 건너뛰기 링크 없음).
  - 용어 26개가 1~26 순서임. 참고 3, 사례 5, 사례 이어서 1, 마지막 맺음말.
  - 화면 문구가 있음. 1, 2 단계는 '저장된 위키' 띠 위에, 3, 4 단계는 '이번 작업의 컨텍스트' 띠 위에 있음.
  - 과장 문구가 없음. 노트에 OKF 출처, 운영 근거, 확인 질문이 있음.
  - 모든 용어 머리말에 '/ 25'가 없음. 표지가 26개임.
  - v21의 46장을 28쪽 뒤로 한 장씩 밀어 대조하면, 용어 번호를 빼고 바뀐 화면은 1, 3, 23, 45(v21 번호)쪽뿐임.
- **기존 검사:** 버전별로 유지했다. 용어 목록은 v22에서만 LLM wiki를 넣은 목록으로 확인하고, v20과 v21의 이전 판 대조는 각 판에만 적용한다. 원래 번호 정수 순서 검사는 문자열 번호(omh-evolution, llm-wiki)를 뺀다.
- **대기와 인쇄:** 화면을 바꿀 때마다 글꼴 준비와 220ms를 기다린다. 인쇄 전에는 글꼴 준비, 두 번의 화면 갱신, 250ms를 기다린다. PDF 제목은 v22다.
