# v21: 15쪽에 OKF 적용 한 줄

2026-10-22 요청에 따라 v20의 15쪽 하단에 다음 문장만 덧붙였다.

> 이후 OKF도 적용: 작업 지식을 정리해 다음 작업에서 재사용

기존 3단계 도식과 얇아진 직접 구현 층은 그대로다. OKF를 OMP 기본 기능 상자에 넣거나 새 페이지로 확장하지 않았다. 총 46장과 다른 45쪽 화면은 유지한다.

사용자는 같은 날 폴더 기반 지식관리 적용 후 동작한다고 보고했다. 이 자기 보고와 OKF의 일반 형식 설명은 구분한다. 내부 구현과 다음 세션 회수 품질을 독립 검증한 것은 아니다. 그 경계와 용어 설명은 발표자 노트에만 적었다.

형식 출처는 [OKF v0.2 명세, 커밋 ad30107](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/ad30107c31c06aec8a7d5636e0d1058118604e6f/SPEC.md)다. 표준 자체가 자동 검색이나 메모리 갱신을 수행한다고 설명하지 않는다.

제작은 제한된 문구 추가이므로 직접 처리했다. 주요 제작 경로를 변경하지 않았다. 이전 버전은 보존하고 공개 main, commit과 push는 이 요청에 포함하지 않는다. HTML/PDF와 검사 기록은 v21로 별도 저장한다. 작업 시간과 위임 대비 부담은 측정하지 않았다.

## 확인 결과

- v21 HTML과 PDF를 생성했다. 총 46쪽과 모든 PDF 쪽 번호를 확인했다.
- 기존 Chrome/Playwright 검사 통과. 탐색, 발표자 노트, 단일 파일 실행과 외부 요청 검사를 유지했으며 콘솔 오류와 외부 요청은 없었다.
- v20과 비교하여 15쪽 외 다른 45쪽 화면은 동일하다. v20 HTML, 목록과 노트를 임시 위치에 재빌드하여 바이트 일치도 확인했다. 기존 v20 산출물 해시는 유지됐다.
- 변경한 15쪽의 HTML 및 PDF 렌더를 직접 확인했다. OKF 한 줄의 한글 표시와 기존 도식 사이에 겹침이 없다.
- 근거 파일은 `slides/v21-check-evidence.json`이다. 사내 OKF 기능 자체를 새로 실행하거나 품질을 측정한 검사는 아니다.
