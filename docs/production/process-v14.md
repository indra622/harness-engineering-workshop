# v14 변경 메모: 14쪽 왼쪽을 진행 과정으로

v14는 v13의 44장에서 14쪽 화면과 노트만 바꿨다. 다른 43장은 v13과 같다.

## 사용자 요청

- 14쪽 OpenCode 순정 쪽에 실제 진행 과정이 빠져 있다.
- 네 단계로 보일 것: 표를 고침, 원본과 비교, 기준에 따라 검토, 필요하면 다시 맡김.
- 아래 '역할 흐름은 설명용' 각주는 화면에서 빼고, '쓰는 이유' 띠를 그 자리로 내릴 것.

## 바뀐 것

- **왼쪽:** 준비물 목록(비교 코드, 검토 기준, 다시 맡기는 연결) 대신, 같은 요청을 진행하는 네 단계를 둔다.
  - 1 표를 고침: 금액 빈칸에 0을 채움
  - 2 원본과 비교: 비교 코드를 짜서 맞춰 봄
  - 3 기준에 따라 검토: 번호, 상품이 그대로인지
  - 4 필요하면 다시 맡김: 고칠 것을 되돌림
  - 4단계에서 1단계로 돌아가는 호박색 점선을 하나 둔다.
  - 머리말은 '같은 일을 직접 꾸려 진행'이다.
- **각주:** 화면 아래 각주를 뺐다. 화면에 대신 넣은 단서는 없다.
- **배치:**
  - 그림 높이를 600에서 650으로 늘리고, 두 패널 높이를 410에서 460으로 늘렸다.
  - '쓰는 이유' 띠는 화면 기준 850~940에서 900~990으로 내렸다. 쪽 번호(1000)와 겹치지 않는다.
- **아래 띠 둘째 줄:** 'OpenCode 순정도 네 단계를 할 수 있지만, 비교 도구와 검토 연결은 직접 준비해야 함'.
- **오른쪽:** 세 역할, 연결 여섯 개, 바뀐 내용 칸은 v13 그대로다. 높이에 맞춰 간격만 넓혔다.
- **그대로 둔 것:** 제목 '빈칸만 채우랬는데, 번호까지 바뀌었다면?'과 요청 문구.

## 사실 경계 (노트에 유지)

- **공정한 비교:** OpenCode 순정의 에이전트도 네 단계를 모두 할 수 있고, 하위 작업을 맡기거나 만들어 둔 스크립트를 다시 쓸 수 있다. 차이는 전용 비교 도구와 검토 연결이 미리 준비돼 있느냐다.
- **실제와 설명용:**
  - 바뀐 내용은 examples/omh-v12/의 합성 예시에 비교 도구를 실제로 실행한 결과다. 이번에는 다시 실행하지 않았다.
  - 역할 흐름은 설명용이다.
  - 화면에서 뺀 각주의 내용은 노트의 '실제로 실행한 것'과 '설명용인 부분'에 그대로 있다.
- **말하지 않는 것:** 자동 관문, 실제 벤치마크, 순정이 못 한다는 주장.

## 검사

- **v13 검사:** 14쪽 라벨 묶음(왼쪽 준비물 머리말, 각주 문구 포함)은 v13에만 적용한다.
- **역할 검사:** 역할과 연결 검사(OMO 안 세 역할, 연결 여섯 개의 순서와 끝점, 점선 되돌림, 총괄을 건너뛰지 않음, 실제 실행 결과 일치)는 v14에도 그대로 적용한다.
- **v14 검사:**
  - 네 단계의 번호와 순서, 위에서 아래로 놓임.
  - 각 단계 글자가 실제로 그려진 범위 안에서 OpenCode 상자 안에 있음.
  - 되돌아가는 점선이 있음.
  - 14쪽에 각주가 없음.
  - '쓰는 이유' 띠의 위쪽이 890 이상이고, 쪽 번호 위쪽보다 위에서 끝남.
- **인쇄:** v12 인쇄 대기(글꼴 준비, 두 번의 화면 갱신, 250ms)와 PDF 제목은 v14에도 적용된다.
