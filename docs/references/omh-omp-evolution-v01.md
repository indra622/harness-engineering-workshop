# OMH에서 OMP로: 전환 경험 자료 v01

기준일: 2026-10-21. 발표 자료 v20의 15쪽(사례 2 이어서, OMH에서 OMP로)에 쓰는 주장과 출처를 정리한다.

## 작성자의 전환 경험 (1차 출처: 작성자 진술, 2026-10-21)

- OpenCode와 OMO 위에 며칠 동안 하네스를 직접 덧붙여 OMH v05까지 만들었다. 덧붙인 것은 역할 조율, 실행과 도구 연결, 업무 도구, omh-rigorous 절차다.
- OMP(Oh My Pi)로 옮겨 보니, 직접 덧붙였던 것 중 상당 부분이 이미 기본으로 들어 있었다. 따로 남길 만한 것은 omh-rigorous 절차 정도였다.
- 며칠 들인 작업이 허무하게 느껴졌다. 그래서 v06은 v05보다 얇게, 내 업무에 필요한 절차만 남기는 쪽으로 정리할 수 있었다.
- 이 경험이 맺음말(46쪽)의 '공부할수록, 오히려 확신이 줄었어요'로 이어진다.

이 내용은 작성자의 경험이다. v05와 v06 패키지를 따로 열어 코드, 테스트, 파일 수, 버전 호환성으로 대조한 기록은 없다.

## 공식 문서로 확인한 일반 기능

출처: [oh-my-pi README, 커밋 57b5663](https://github.com/can1357/oh-my-pi/blob/57b56631ee009098a78d9badf91afc3a48eef32e/README.md) (2026-10-21 확인)

- 파일을 읽고, 쓰고, 고치는 기본 도구가 있다.
- 명령 실행 기능이 있다.
- 하위 에이전트에 작업을 맡기고 조율하는 기능이 있다.

15쪽의 'OMP 기본 기능' 세 줄은 이 일반 기능만 가리킨다. 지금의 공식 문서가 작성자가 설치해 쓴 버전과 같다는 것을 보여 주지는 않는다. 도구 개수, 계속 바뀌는 기능 목록, 모델 관련 내용은 옮기지 않았다.

## 말하지 않는 것

- OMH의 data_inspect, data_compare 같은 업무 도구가 OMP에 같은 방식이나 같은 결과 형식으로 들어 있다거나, 그대로 대체된다는 주장. 화면에 이 도구 이름을 쓰지 않았다.
- 크기, 코드 줄 수, 압축 파일 용량, 측정한 성능이나 속도.
- 하네스가 필요 없어졌다는 결론. 바탕 도구가 많은 것을 기본으로 갖추면, 직접 덧붙일 부분이 얇아질 수 있다는 경험담이다.

## 점검 범위

- OMH v05, v06 패키지의 코드나 실행 결과는 점검하지 않았다. 이 자료를 만들며 OMP를 설치하거나 실행하지도 않았다.
- 화면의 전환 경험(v05까지 며칠, OMP로 옮긴 결과, 얇아진 v06)은 작성자 진술에서, OMP의 기본 기능은 위 공식 README에서 가져왔다.
- 14쪽의 실제 도구 실행 결과(examples/omh-v12/)는 OMH v04 엔진의 결과이며, 이 전환 경험과는 별개다.
